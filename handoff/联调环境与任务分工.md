## 四、所有接口的四条通用规矩

1. **信封**：成功 `{data, meta}`；失败 `{code, message, details, requestId, timestamp}`。
2. **登录凭证**：`POST /auth/password-login`（body: `{account, password}`）→ `accessToken`（15 分钟）+ `refreshToken`；每个请求带 `Authorization: Bearer <accessToken>`；401 时 `POST /auth/refresh` 换新。
3. **所有写操作必须带 `Idempotency-Key` 请求头**（随机 UUID），否则 VALIDATION_FAILED。
4. **改数据带 `expectedVersion`**（对象上的 `version` 字段）；报 `CONFLICT_VERSION_MISMATCH` 就重读再试。

`SYSTEM_MODE_UNSUPPORTED` = "该功能后端暂未开放"（30 个新接口的统一回复），界面显示"暂未开放"，**不是 bug、不要重试**。

**现成参考实现**：`BNBU-web/frontend/student/js/api.js` —— token 存储、自动刷新、信封解析、错误文案、幂等键、媒体上传全写好了，翻成 TypeScript 即可复用。

## 七、已经踩过的坑（能省很多时间）

1. **学生不能重复入班**：同一学生同一班二次 join 报 `ENROLLMENT_ALREADY_ACTIVE`。学生"再次登录"依赖尚未开放的验证码登录——**测试学生端丢了登录态就换一个新学号**。这是要催后端的第一优先级缺口。
2. **邀请码区分大小写**，任何地方都不要 toUpperCase（门户 `course-invite.ts` 里现在就有一处，见天哥卡第 3 条）。
3. **照片四步上传后要轮询**：initiate → PUT → confirm(ETag) → bind，然后轮询 `GET /media/{id}` 等 `uploadStatus=AVAILABLE` 再提交，否则 `MEDIA_NOT_AVAILABLE`。
4. **运动要按后端时钟真满 1 小时**才计学时（`EXERCISE_RECORD_DURATION_NOT_CREDITABLE`）；本地想快速造数据找组长改数据库。
5. **业务日期以后端时区为准**，可能和本机差一天。
6. **数据库有防篡改触发器**：记录/会话表不许删改（审计要求）。测试数据错了优先新建，不要改旧的。
